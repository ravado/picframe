# Plan: Restore Backward Compatibility with Upstream picframe

## Context

The `ravado/picframe` fork (based on `helgeerbe/picframe`) has accumulated custom features (DHT22/BME280 sensors, GPIO clap detection, MQTT sensor publishing) that are **not backward compatible** with the upstream repo. Custom code is wired directly into core files (`start.py`, `viewer_display.py`, `controller.py`, `interface_mqtt.py`, `model.py`) without proper defaults, graceful fallbacks, or config initialization. Running this fork without the custom YAML config sections causes `KeyError` crashes at startup.

**Goal:** Make all custom features opt-in with safe defaults so the fork can:
1. Run cleanly without any custom config sections (upstream-compatible)
2. Be properly initialized via `picframe -i` with all needed configs
3. Allow future upstream merges with minimal conflict

### Step 4: Make `start.py` import and usage conditional

**File:** `picframe/src/picframe/start.py`

Change line 8 to remove `gpio_actions` from the unconditional import:

```python

```

Make GPIO initialization conditional on config:

```python
m = model.Model(...)
v = viewer_display.ViewerDisplay(m.get_viewer_config())
c = controller.Controller(m, v)

# Only init GPIO if enabled in config
gpio_config = m.get_gpio_config()
if gpio_config.get('use_gpio', False):
    try:
        from picframe import gpio_actions
        gpio_controller = gpio_actions.GpioController(c, gpio_config)
    except ImportError:
        logging.getLogger("start.py").warning("gpio_actions unavailable, skipping GPIO")

c.start()
```
